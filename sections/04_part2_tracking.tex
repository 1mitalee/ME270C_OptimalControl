\subsection{Trajectory Tracking Formulation}

In Part I, the LQR problems were formulated in terms of deviation variables
\[
    \delta x(t) = x(t)-x^\star(t),
    \qquad
    \delta u(t) = u(t)-u^\star(t),
\]
where \(x^\star(t)\) and \(u^\star(t)\) denote the nominal state and control trajectory about which the nonlinear dynamics are linearized. Therefore, the finite-horizon LQR problem was already written as a regulation problem for perturbations about a nominal trajectory.

The trajectory tracking problem has the same fundamental structure. Let
\[
    x_{\mathrm{ref}}(t),
    \qquad
    u_{\mathrm{ref}}(t)
\]
denote the desired reference trajectory and reference input. The tracking error and input deviation are defined by
\[
    e(t) = x(t)-x_{\mathrm{ref}}(t),
    \qquad
    \eta(t)=u(t)-u_{\mathrm{ref}}(t).
\]
Equivalently, in the notation used in the previous sections, these are the deviation variables
\[
    e(t) \equiv \delta x(t),
    \qquad
    \eta(t) \equiv \delta u(t).
\]
Thus, the LQR tracking problem is again a finite-horizon LQR problem in deviation coordinates.

The nonlinear dynamics are
\[
    \dot x = f(x,u).
\]
If the system is linearized about the reference trajectory itself, and if the reference trajectory satisfies
\[
    \dot x_{\mathrm{ref}}(t)=f(x_{\mathrm{ref}}(t),u_{\mathrm{ref}}(t)),
\]
then the first-order tracking-error dynamics are
\[
    \dot e(t)
    =
    A_{\mathrm{ref}}(t)e(t)
    +
    B_{\mathrm{ref}}(t)\eta(t),
\]
where
\[
    A_{\mathrm{ref}}(t)
    =
    \left.
    \frac{\partial f}{\partial x}
    \right|_{(x_{\mathrm{ref}}(t),u_{\mathrm{ref}}(t))},
    \qquad
    B_{\mathrm{ref}}(t)
    =
    \left.
    \frac{\partial f}{\partial u}
    \right|_{(x_{\mathrm{ref}}(t),u_{\mathrm{ref}}(t))}.
\]


\subsection{PMP and Tracking Riccati Equations}
In our interpretation of the problem, the linearized dynamics have already been constructed in terms of deviations from a trajectory. Therefore, the tracking formulation is not fundamentally different from the finite-horizon LQR formulation in Part I. The primary distinction is that the trajectory used to define the tracking error need not be the same as the trajectory used to compute the linearization matrices. In other words, the matrices \(A(t)\) and \(B(t)\) may be obtained from a nominal trajectory, while the cost penalizes deviation from a desired reference trajectory.

Figure~\ref{fig:tracking-position} shows the resulting trajectory in the physical \((p_x,p_z)\)-plane. trajectory begins far from the reference, but moves toward the reference terminal region over the finite horizon.

The tracking-error components are shown in Figure~\ref{fig:tracking-errors}. The horizontal and vertical position errors \(e_{p_x}\) and \(e_{p_z}\) decrease substantially over the horizon. In particular, the position errors are close to zero near the terminal time, which indicates that the controller is effective at driving the tracked trajectory toward the reference trajectory in position space. 
\begin{figure}[H] \centering \includegraphics[width=0.4\textwidth]{sections/PART6/tracking_errors.png} \caption{Tracking-error components \(e(t)=\delta x(t)-\delta x_{\mathrm{ref}}(t)\).} \label{fig:tracking-errors} \end{figure}
The velocity and attitude errors show a more oscillatory response. The horizontal velocity error initially increases before decreasing, while the vertical velocity error becomes negative and remains nonzero at the final time. Similarly, the attitude and angular-velocity errors exhibit transient oscillations. This behavior is expected because the hover linearization controls horizontal motion indirectly through the attitude dynamics. 
Therefore, correcting large position errors requires nontrivial attitude and angular-velocity corrections. Figure~\ref{fig:tracking-correction-controls} shows the correction controls \[ v(t)=\delta u(t)-\delta u_{\mathrm{ref}}(t). \]
\begin{figure}[H] \centering \includegraphics[width=0.4\textwidth]{sections/PART6/tracking_correction_controls.png} \caption{Tracking correction controls \(v(t)=\delta u(t)-\delta u_{\mathrm{ref}}(t)\).} \label{fig:tracking-correction-controls} \end{figure} \begin{figure}[H] \centering \includegraphics[width=0.4\textwidth]{sections/PART6/tracking_true_controls.png} \caption{Physical controls obtained after adding the reference input and hover trim input.} \label{fig:tracking-true-controls} \end{figure} 

\subsection{Discussion: Reference Trajectory Availability}
% TODO: Discuss limitations when the reference trajectory is not known in advance.

If the reference trajectory is available only online, the tracking problem should be interpreted in a receding-horizon sense. At each time, the controller uses the currently available reference information to define the error and computes a correction. If a short future reference window is available, the same finite-horizon Riccati/PMP equations are solved repeatedly on a moving horizon. If only the instantaneous reference is available, then the controller becomes a causal local tracking controller rather than a full finite-horizon optimal tracker.
